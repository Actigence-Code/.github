# Project governance

Maintainers steward the repository, review contributions and decide when a change is ready for release. Contributors propose focused changes with enough context and validation for someone else to review them.

## Decisions and review

Use a pull request to explain the problem, the chosen behavior, compatibility considerations and the checks performed. Discuss significant cross-project contracts in Actigence Core before implementing separate variants. Application-specific decisions stay with the application.

Keep decisions understandable to future contributors. Record accepted design choices in the relevant project documentation, and distinguish proposals from completed work. Do not place confidential discussions, customer evidence or personal information in decision records.

## Releases

A release identifies an exact commit and describes its scope, validation and known limits. Maintenance releases for repository standards are separate from application or package releases. Do not claim a deployment, registry publication or binary build merely because a GitHub release exists.

## Participation

Follow [CONTRIBUTING.md](CONTRIBUTING.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Use [SUPPORT.md](SUPPORT.md) for ordinary questions and the private reporting process in [SECURITY.md](SECURITY.md).
